### [2026-10-31] [workflow] アプリが書き換えた設定を「元に戻す」と勧める前に、スキーマと本人の操作を確かめる

**Mistake**: cmux が cmux.json の shortcuts を消したのを見て、確かめずに「元に戻す」を推奨し、戻した。実際はユーザーが cmux でショートカットをリセットしたもので、元の書き方はスキーマ違反だった（PR #12 で判明）
**Root cause**: 差分だけを見て「アプリが壊した」と決めつけ、`cmux config validate` も、いつ誰が設定を変えたかも見なかった
**Rule**: アプリが書き換えた設定ファイルを戻す案を出す前に、(1) そのアプリの検証コマンド（例 `cmux config validate --path`）で両方の版を確かめる (2) ユーザーに設定を変えた覚えがあるかを選択肢に入れる
**Verification**: 戻す提案の中に、検証コマンドの結果が書いてあること
**Applies to**: all projects

### [2026-11-02] [communication] 別の場所で進む issue の状態を、古い取得結果のまま「進行中」と報告した

**Mistake**: DEV-234 を 13:37 ごろに取得した結果（In Progress）のまま、15:30 すぎの報告で「別のワークスペースで進行中」と書いた。実際は 14:40 に agents の PR #67 がマージされ、Done になっていた
**Root cause**: 別のワークスペースの issue は、こちらが見ていない間に進む。報告の直前に取り直さなかった
**Rule**: 「残っていること」に他のタブ・ワークスペースの issue を書く前に、Linear の状態をその場で取り直す
**Verification**: 報告の「残っていること」の各 issue に、同じ返答の中で取得した状態が対応している
**Applies to**: all projects
